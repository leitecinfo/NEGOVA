## 1. Objetivo

Definir cómo NEGOVA encapsula las operaciones dentro del **Contexto del Negocio Activo** (`business_id`), impidiendo que una sesión autenticada asuma de forma implícita un único establecimiento.

---

# 2. El Modelo Multi-Membresía

```text
                     USUARIO (Juan Pérez)
                               │
             ┌─────────────────┴─────────────────┐
             ▼                                   ▼
    [Restaurante La Playa]              [Tienda Central]
    business_id = A                     business_id = B
    Rol: PROPIETARIO                    Rol: PERSONAL
             │
             ▼ (Contexto Activo Seleccionado)
    ┌──────────────────────────────────────────────────┐
    │ Todas las mutaciones (orders, menu, expenses)   │
    │ se firman y evalúan contra business_id = A       │
    └──────────────────────────────────────────────────┘
```

> 🔒 **Regla de Oro:** Cambiar de contexto no otorga permisos de forma mágica; el servidor re-evalúa de forma autoritaria la membresía y permisos en el nuevo `business_id`.
