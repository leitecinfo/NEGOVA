## 1. Objetivo

Definir el modelo de seguridad integral por capas (*Defense-in-Depth*) de NEGOVA, asegurando que ninguna capa o componente sea considerado suficiente por sí solo para otorgar acceso a los datos u operaciones.

---

# 2. Pipeline Concéntrico de Seguridad

```text
Usuario Real (Operador / Cliente)
       ↓
1. Autenticación (Supabase Auth / JWT)
       ↓
2. Sesión Segura (Cookies HTTP-Only)
       ↓
3. Identidad de Usuario (public.users)
       ↓
4. Contexto del Negocio / Tenant (business_id)
       ↓
5. Rol Asignado (business_users.role_id)
       ↓
6. Permiso Granular Requerido (role_permissions)
       ↓
7. Regla de Negocio y Validación (Zod en Servidor)
       ↓
8. Row Level Security (RLS en PostgreSQL)
       ↓
Persistencia Segura en Base de Datos
```

> 🔒 **Principio Fundamental:** La seguridad de NEGOVA es acumulativa y obligatoria. Si cualquiera de los 8 eslabones del pipeline falla o no se cumple, la operación es **rechazada inmediatamente con error 401 o 403**.
