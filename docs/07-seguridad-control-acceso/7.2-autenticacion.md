## 1. Objetivo

Definir la arquitectura de autenticación de NEGOVA, responsable exclusiva de validar la identidad técnica del usuario (**¿Quién eres?**) mediante **Supabase Auth**, manteniendo esta responsabilidad completamente desacoplada de la autorización.

---

# 2. Alcance Operativo de Autenticación

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Registro de Nuevas Cuentas (Sign Up)                     │
│ 2. Inicio de Sesión Seguro (Sign In con Email y Password)   │
│ 3. Cierre de Sesión e Invalidación de Tokens (Sign Out)     │
│ 4. Verificación de Correo Electrónico                       │
│ 5. Flujo de Recuperación de Contraseña (Forgot Password)    │
│ 6. Actualización Segura de Contraseña                       │
│ 7. Emisión y Rotación de Tokens JWT (Access / Refresh)      │
│ 8. Control Automático de Expiración de Sesión               │
└─────────────────────────────────────────────────────────────┘
```

> ⚠️ **Separación Conceptual:** La autenticación únicamente certifica que el usuario es quien dice ser. **No otorga permisos ni define a qué negocios puede acceder** (responsabilidad de la capa de autorización).
