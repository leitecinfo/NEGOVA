## 1. Objetivo

Definir el conjunto oficial de tecnologías, librerías, frameworks e infraestructura de despliegue que componen la plataforma SaaS Multi-Tenant de NEGOVA.

El stack está seleccionado para maximizar la velocidad de desarrollo, garantizar mantenibilidad a largo plazo, ofrecer rendimiento fluido en redes móviles y asegurar un aislamiento impenetrable de datos entre negocios.

# 3. Decisiones Arquitectónicas Clave (Trade-Offs)

### 3.1 Sin ORM Pesado (No Prisma)
- **Decisión:** NEGOVA interactúa directamente con Supabase mediante `@supabase/ssr` y tipos generados automáticamente con `supabase gen types typescript`.
- **Razón:** Elimina la latencia de arranque en frío (*cold starts*) de Prisma en funciones serverless de Vercel y permite aprovechar al 100% las funciones nativas de PostgreSQL y políticas RLS.

### 3.2 Sin Servidor Node.js / Express Separado
- **Decisión:** El backend se ejecuta como un **Monolito Modular Serverless** utilizando **Next.js Server Actions** y **Route Handlers**.
- **Razón:** Reduce la complejidad operativa, abarata costos de hosting y unifica el código en un único repositorio TypeScript.

### 3.3 UI con shadcn/ui y Prohibición de Alertas Nativas
- **Decisión:** Componentes desacoplados construidos sobre Radix UI y Tailwind CSS.
- **Regla Estricta:** Queda **terminantemente prohibido el uso de alertas nativas** (`alert`, `confirm`, `prompt`). Toda confirmación de riesgo se implementa con **Modales Personalizados** (`AlertDialog` de shadcn/ui) y las notificaciones mediante **Toasts** (`Sonner`).
