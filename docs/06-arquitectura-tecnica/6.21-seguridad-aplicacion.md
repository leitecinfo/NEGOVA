## 1. Objetivo

Definir los principios y mecanismos de seguridad de la aplicación en todas sus capas, garantizando que el sistema opere bajo el modelo de *Zero-Trust*, donde el frontend nunca es la autoridad de seguridad y toda acción se valida en servidor y base de datos.

---

# 2. Principios Rectores de Seguridad

```text
1. Deny by default:      Todo acceso está denegado salvo que exista una regla explícita que lo autorice.
2. Least privilege:      Cada usuario y servicio opera con los permisos estrictamente indispensables.
3. Server-side check:    La seguridad reside en Server Actions y PostgreSQL RLS, no en ocultar botones en UI.
4. Tenant isolation:     Aislamiento absoluto e impenetrable entre los datos de diferentes negocios.
5. Secure defaults:      Configuraciones seguras por defecto (HTTPS, cookies seguras, hashing robusto).
```

---

# 3. La Pregunta de Seguridad en Cada Operación

Para toda mutación o consulta, el pipeline evalúa:
$$\text{¿Quién es?} \land \text{¿Está autenticado?} \land \text{¿Pertenece al negocio?} \land \text{¿Qué rol tiene?} \land \text{¿Tiene el permiso?} \land \text{¿El recurso es de su negocio?}$$
