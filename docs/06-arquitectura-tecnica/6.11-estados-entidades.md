## 1. Objetivo

Definir las máquinas de estados finitos, transiciones permitidas, roles autorizados y efectos colaterales para las entidades clave de NEGOVA, garantizando que ninguna entidad cambie de estado de manera arbitraria.

---

# 2. Máquinas de Estados del MVP

### 2.1 Ciclo de Vida del Negocio (`businesses.status`)
```text
  [ trial ] ──► [ active ] ──► [ suspended ] ──► [ inactive ]
      │             │               │
      └─────────────┴───────────────┴──► [ cancelled ]
```

### 2.2 Ciclo de Vida de Productos (`products.status`)
```text
  [ active ] ◄──► [ inactive ] ──► [ archived ]
```

### 2.3 Máquina de Estados de Comandas (`orders.status`)
```text
  [ RECEIVED ] (Recibido por WhatsApp / Menú Web)
       │
       ▼
  [ CONFIRMED ] (Aprobado por el personal de cocina)
       │
       ▼
  [ PREPARING ] (En plancha / freidora)
       │
       ▼
  [ READY ] (Empacado y listo para entregar/despachar)
       │
       ├───────────────────────────────┐
       ▼ (Si es a Domicilio)           ▼ (Si es en Mostrador)
  [ OUT_FOR_DELIVERY ]                 │
       │                               │
       ▼                               │
  [ DELIVERED ]                        │
       │                               │
       └───────────────┬───────────────┘
                       ▼
                 [ COMPLETED ] (Pagado y archivado)

  * Nota: En cualquier momento previo a COMPLETED puede pasar a [ CANCELLED ].
```

---

# 3. Reglas de Transición y Auditoría

1. **Permisos Requeridos:** Las transiciones de comanda (`orders.manage`) solo pueden ser ejecutadas por usuarios con membresía activa (`owner` o `staff`).
2. **Registro Automático:** Todo cambio en `orders.status` dispara un trigger PostgreSQL que asienta el estado anterior, nuevo estado, actor (`auth.uid()`) y marca temporal en `order_status_history`.
