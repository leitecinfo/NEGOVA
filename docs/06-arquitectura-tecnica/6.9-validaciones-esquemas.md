## 1. Objetivo

Definir la estrategia de validación de datos en dos niveles (Cliente y Servidor) mediante esquemas tipados **Zod**, asegurando que ninguna información corrupta, malformada o de otro tenant sea procesada.

---

# 2. Los Dos Niveles de Validación

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. VALIDACIÓN EN CLIENTE (Experiencia de Usuario / UX)      │
│    - React Hook Form + Zod Resolver                         │
│    - Feedback visual inmediato (campos requeridos, formato) │
├─────────────────────────────────────────────────────────────┤
│ 2. VALIDACIÓN EN SERVIDOR (Barrera de Seguridad Real)       │
│    - Esquemas Zod ejecutados en Server Actions              │
│    - Validación de límites numéricos (precios >= 0)         │
│    - Verificación de pertenencia al mismo tenant            │
└─────────────────────────────────────────────────────────────┘
```

---

# 3. Validación Relacional Multi-Tenant

> ⚠️ **Regla Crítica:** Un payload con UUIDs técnicamente válidos no es necesariamente legítimo. El servidor debe verificar que las entidades relacionadas pertenezcan al mismo `business_id`:

$$\text{Producto (Negocio A)} + \text{Categor\text{í}a (Negocio B)} \quad \mathbf{\times\ (RECHAZADO)}$$
