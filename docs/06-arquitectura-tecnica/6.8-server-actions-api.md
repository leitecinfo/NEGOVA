## 1. Objetivo

---

# 2. Pipeline de Ejecución de una Server Action

Toda mutación de backend en NEGOVA implementa un pipeline estricto de 9 pasos:

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. Recepción de solicitud desde componente visual UI        │
│ 2. Extracción de sesión JWT (auth.uid)                      │
│ 3. Verificación de existencia del business_id               │
│ 4. Validación de membresía activa en business_users         │
│ 5. Comprobación de permisos granulares (RBAC)               │
│ 6. Validación de tipos y formato con esquema Zod            │
│ 7. Ejecución de reglas de negocio en base de datos (Postgres)│
│ 8. Registro automático en audit_logs / triggers             │
│ 9. Retorno de respuesta tipada { success: true, data }      │
└─────────────────────────────────────────────────────────────┘
```

---

# 3. Separación Estructural: Queries vs. Actions vs. Services

```text
src/features/[feature]/
├── queries/          --> Lecturas optimizadas (SELECT) sin efectos secundarios
├── actions/          --> Mutaciones de estado (INSERT, UPDATE, DELETE) con validación
└── services/         --> Integraciones externas (WhatsApp, Pasarelas, Envíos)
```
