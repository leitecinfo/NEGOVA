## 1. Objetivo

Definir la política de copias de seguridad (*Backups*), recuperación en el tiempo (*Point-In-Time-Recovery - PITR*) y el plan de contingencia ante desastres (*Disaster Recovery*) para salvaguardar la información operacional y financiera de todos los negocios en NEGOVA.

---

# 2. Matriz de Estrategia de Respaldo

| Dimensión | Política Establecida |
| :--- | :--- |
| **¿Qué se respalda?** | 100% de la base de datos PostgreSQL (todas las tablas, enums, triggers y RLS) + Supabase Storage. |
| **Frecuencia** | Copias de seguridad automáticas diarias + WAL Logs continuos (PITR). |
| **Retención** | Respaldos diarios retenidos por 30 días; respaldos mensuales retenidos por 1 año. |
| **Ubicación** | Almacenamiento redundante en región secundaria cifrado con AES-256. |
| **Acceso** | Restringido exclusivamente al Super Administrador / DevOps mediante autenticación MFA. |
| **Verificación** | Pruebas de restauración trimestrales en entorno de pruebas (*Staging*). |

---

# 3. Métricas Objetivo de Recuperación (RPO & RTO)

- **Recovery Point Objective (RPO):** $< 5 \text{ minutos}$ (gracias al streaming WAL continuo de Supabase).
- **Recovery Time Objective (RTO):** $< 30 \text{ minutos}$ para restablecer el servicio operativo completo en caso de fallo catastrófico.
