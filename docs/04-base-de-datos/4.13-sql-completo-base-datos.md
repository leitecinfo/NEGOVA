## 1. Arquitectura de Aislamiento y Principios Rectores

Esta especificación técnica e implementación DDL garantiza el aislamiento absoluto, la integridad referencial compuesta y la seguridad multi-tenant de **NEGOVA**.

```text
                                PLATAFORMA NEGOVA
                                        │
           ┌────────────────────────────┴────────────────────────────┐
           │                                                         │
   CAPA DE PLATAFORMA (Global)                               CAPA DE TENANTS (Aislada)
   ├── platform_settings                                     └── businesses (Tenants)
   ├── features / plan_features                                  ├── business_settings
   ├── plans / subscriptions                                     ├── business_features
   └── roles / permissions (Scope: Platform & Business)          └── business_users (Membresías)
                                                                      │
                                         ┌────────────────────────────┼────────────────────────────┐
                                         ▼                            ▼                            ▼
                                  CATÁLOGO Y VENTAS               LOGÍSTICA Y CLIENTES          FINANZAS Y CONTROL
                                  ├── categories                  ├── customers                 ├── payments
                                  ├── products                    ├── customer_addresses        ├── expense_categories
                                  ├── product_option_groups       ├── deliveries (1:0..1)       ├── expenses
                                  ├── product_options             └── notifications             ├── files (Storage)
                                  ├── orders (consecutivo propio)                               └── audit_logs
                                  ├── order_items (inmutable)
                                  ├── order_item_options
                                  └── order_status_history
```

# 2. Las 15 Correcciones de Integridad y Endurecimiento Integradas

1. **Integridad Referencial Cruzada por `business_id` (Composite Foreign Keys):**  
   Todas las tablas hijas (`order_items`, `deliveries`, `payments`, `product_options`, `customer_addresses`, etc.) implementan claves foráneas compuestas del tipo `FOREIGN KEY (parent_id, business_id) REFERENCES parent_table(id, business_id)`. Esto hace **matemáticamente imposible** que un pedido del Negocio A asocie un producto o cliente del Negocio B.
2. **Usuarios Globales y Membresías Independientes:**  
   Separación limpia entre la identidad global (`public.users`, sincronizada con `auth.users`) y la membresía local (`public.business_users`), permitiendo que una misma persona participe en múltiples comercios con roles diferentes.
3. **Control de Acceso RBAC con Doble Ámbito (`role_scope`):**  
   Diferenciación estricta entre roles de plataforma (`super_admin`) y roles de comercio (`owner`, `admin`, `staff`), con matriz granular de permisos por módulo.
4. **Protección y Gobernanza de Super Admin:**  
   Funciones de seguridad con `SECURITY DEFINER` y verificación explícita de ámbito para evitar bypasses accidentales en la lógica de tenants.
5. **Planes y Suscripciones Resilientes:**  
   Manejo de estados de suscripción (`trialing`, `active`, `past_due`, `cancelled`), límites en formato JSONB e historial de facturación en `subscription_invoices`.
6. **Catálogo con Modificadores Flexibles:**  
   Estructura completa de grupos de opciones (`min_selections`, `max_selections`, `required`), opciones con precios adicionales y switch rápido de disponibilidad (`is_available = false`).
7. **Pedidos con Doble Congelamiento Histórico:**  
   `order_items` y `order_item_options` almacenan copia inmutable del nombre y precio en el instante de la transacción.
8. **Clientes y Direcciones Normalizadas:**  
   Directorio de clientes con soporte multi-dirección (`customer_addresses`) y referencias comunitarias (sin obligar GPS satelital).
9. **Finanzas y Cuadre de Caja:**  
   Separación de ingresos por método (`cash`, `transfer`, `card`), auditoría de abonos parciales y categorización de egresos en `expenses`.
10. **Auditoría Inmutable (Audit Logs):**  
    Registro transaccional de quién, cuándo y qué cambió (`old_data` vs. `new_data`).
11. **Almacenamiento de Archivos (Supabase Storage):**  
    Metadatos de imágenes y documentos vinculados a cada comercio en `public.files`.
12. **Notificaciones Multicanal:**  
    Registro de notificaciones dirigidas por usuario y negocio (`in_app`, `email`, `whatsapp`).
13. **Row Level Security (RLS) Endurecido y Políticas Públicas:**  
    Políticas RLS en el 100% de tablas. Los clientes anónimos del Menú Digital solo pueden leer catálogo activo/disponible e insertar órdenes en estado `received`.
14. **Triggers y Automatizaciones de Producción:**  
    - Auto-actualización de `updated_at`.
    - Auto-creación de perfil en `public.users` al registrarse en `auth.users`.
    - Auto-auditoría cronológica en `order_status_history`.
    - Generación atómica del número consecutivo de orden (`order_number`) por comercio.
15. **Índices B-Tree de Alto Rendimiento:**  
    Optimización de consultas en horas pico de cocina y filtros multi-tenant.

-- 10.2 Auto-creación de perfil de usuario al registrarse en Supabase Auth
CREATE OR REPLACE FUNCTION public.handle_new_auth_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.users (id, full_name, phone, status, created_at, updated_at)
  VALUES (
    NEW.id,
    COALESCE(NEW.raw_user_meta_data->>'full_name', NEW.email),
    NEW.phone,
    'active',
    now(),
    now()
  )
  ON CONFLICT (id) DO NOTHING;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

DROP TRIGGER IF EXISTS trg_on_auth_user_created ON auth.users;
CREATE TRIGGER trg_on_auth_user_created
AFTER INSERT ON auth.users
FOR EACH ROW EXECUTE FUNCTION public.handle_new_auth_user();


-- 10.3 Auto-asignación de consecutivo único de pedido por negocio
CREATE OR REPLACE FUNCTION public.assign_order_number()
RETURNS TRIGGER AS $$
DECLARE
  next_num BIGINT;
BEGIN
  IF NEW.order_number IS NULL OR NEW.order_number = 0 THEN
    SELECT COALESCE(MAX(order_number), 0) + 1 
    INTO next_num 
    FROM public.orders 
    WHERE business_id = NEW.business_id;
    
    NEW.order_number = next_num;
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_orders_assign_number ON public.orders;
CREATE TRIGGER trg_orders_assign_number
BEFORE INSERT ON public.orders
FOR EACH ROW EXECUTE FUNCTION public.assign_order_number();


-- 10.4 Auto-auditoría de transiciones de estado en la comanda
CREATE OR REPLACE FUNCTION public.handle_order_status_audit()
RETURNS TRIGGER AS $$
BEGIN
  IF (TG_OP = 'INSERT') THEN
    INSERT INTO public.order_status_history (
      business_id,
      order_id,
      previous_status,
      new_status,
      changed_by,
      created_at
    ) VALUES (
      NEW.business_id,
      NEW.id,
      NULL,
      NEW.status,
      auth.uid(),
      now()
    );
  ELSIF (TG_OP = 'UPDATE' AND OLD.status IS DISTINCT FROM NEW.status) THEN
    INSERT INTO public.order_status_history (
      business_id,
      order_id,
      previous_status,
      new_status,
      changed_by,
      created_at
    ) VALUES (
      NEW.business_id,
      NEW.id,
      OLD.status,
      NEW.status,
      auth.uid(),
      now()
    );
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

DROP TRIGGER IF EXISTS trg_orders_status_audit ON public.orders;
CREATE TRIGGER trg_orders_status_audit
AFTER INSERT OR UPDATE ON public.orders
FOR EACH ROW EXECUTE FUNCTION public.handle_order_status_audit();

-- 11. FUNCIONES AUXILIARES DE AUTORIZACIÓN Y RLS
-- ============================================================

CREATE OR REPLACE FUNCTION public.user_has_business_access(target_business_id UUID)
RETURNS BOOLEAN LANGUAGE sql SECURITY DEFINER STABLE SET search_path = public AS $$
  SELECT EXISTS (
    SELECT 1 FROM public.business_users
    WHERE business_id = target_business_id 
      AND user_id = auth.uid() 
      AND status = 'active'
  );
$$;

CREATE OR REPLACE FUNCTION public.user_has_permission(target_business_id UUID, permission_code TEXT)
RETURNS BOOLEAN LANGUAGE sql SECURITY DEFINER STABLE SET search_path = public AS $$
  SELECT EXISTS (
    SELECT 1 FROM public.business_users bu
    JOIN public.role_permissions rp ON rp.role_id = bu.role_id
    JOIN public.permissions p ON p.id = rp.permission_id
    WHERE bu.business_id = target_business_id 
      AND bu.user_id = auth.uid() 
      AND bu.status = 'active' 
      AND p.code = permission_code
  );
$$;

CREATE OR REPLACE FUNCTION public.is_super_admin()
RETURNS BOOLEAN LANGUAGE sql SECURITY DEFINER STABLE SET search_path = public AS $$
  SELECT EXISTS (
    SELECT 1 FROM public.business_users bu
    JOIN public.roles r ON r.id = bu.role_id
    WHERE bu.user_id = auth.uid() 
      AND r.scope = 'platform' 
      AND r.code = 'super_admin'
  );
$$;
