## 1. Objetivo

Documentar exhaustivamente el significado, propósito, tipo de dato y comportamiento de cada uno de los campos que componen las 15 tablas de la base de datos de NEGOVA.

Este documento complementa el modelo lógico (4.2) y el diagrama entidad-relación (4.3), sirviendo como especificación técnica directa para el desarrollo del backend, APIs y esquemas de base de datos en Supabase/PostgreSQL.

# 2. `businesses` (Tenants / Comercios)

Representa la cuenta comercial raíz de aislamiento de datos en NEGOVA.

| Campo | Tipo lógico | Obligatorio | Descripción |

# 17. Reglas generales de integridad de datos

### 17.1 Identificadores Inmutables
Toda entidad utiliza un identificador primario de tipo `UUID v4`, garantizando unicidad global y seguridad contra enumeración de URLs.

### 17.2 Auditoría y Marcas Temporales
Todas las tablas incluyen `created_at` y `updated_at` con tipos `timestamptz` (almacenamiento en UTC) para soportar zonas horarias correctas (ej. `America/Bogota` / UTC-5).

### 17.3 Precisión Monetaria
Todos los importes monetarios (`price`, `subtotal`, `delivery_fee`, `total`, `amount`) se definen como `numeric(12,2)`.  
> ⚠️ **Prohibición:** Queda terminantemente prohibido el uso de tipos de coma flotante (`float`, `double`, `real`) para almacenar dinero.

### 17.4 Integridad Referencial y Eliminación Lógica
Las tablas transaccionales no se eliminan físicamente. La inhabilitación de catálogo se efectúa mediante `is_available = false` o `status = 'INACTIVE'`, preservando la integridad de reportes históricos.

# 18. Principio de separación: Datos Actuales vs. Datos Históricos

```text
       CATÁLOGO DE PRODUCTOS (Actual)                  LÍNEA DE PEDIDO (Histórico)
┌───────────────────────────────────────────┐   ┌───────────────────────────────────────────┐
│ products.price       = $15.000 COP        │   │ order_items.unit_price = $13.000 COP      │
│ products.name        = "Hamburguesa Doble"│   │ order_items.product_name = "Hamburguesa"  │
└───────────────────────────────────────────┘   └───────────────────────────────────────────┘
                      ▲                                               │
                      └──────── Modificaciones futuras NO alteran ────┘
```
